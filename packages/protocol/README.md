# Shared Flex intents

`@flex/protocol` owns the agent–wallet contract. Both layers import its types, JSON schema, semantic validation (`checkEnvelope`), mapping (`toPlan`) and execution report types. The canonical handoff is **version 2**; neither layer accepts a v1 handoff as a new request.

| Intent | Shared fields and meaning | Changes from the old agent handoff |
| --- | --- | --- |
| `i` — pay now | `recipients[]` contains each address and exact amount; `token`, `token_address`, `chain_id`, `depends_on` identify the asset and funding dependencies. One step pays atomically, with up to 100 distinct recipients. | Replaces scalar `recipient` / `amount`. Compatible payments can share a step; repeated addresses use separate steps. |
| `j` — bridge | USDC amount, source/destination chain and registered token addresses, `receiver: "self"`, `funds_steps`, and `fee_max_eth` (native ETH on the source chain). | Adds an explicit ETH fee ceiling. ETH bridging is unsupported. The token buffer and ETH fee are different quantities; the default token buffer is now zero. |
| `k` — autopay | `autopay_id`, up to 50 `recipients`, `fee: {to, amount}`, fixed UTC `schedule`, `limits: {max_per_run, max_total}`, `executor: "chainlink-cre"`, asset and dependency fields. Caps include payees **and** the per-run fee. | Replaces calendar/cron, prefunding and private-delegate assumptions. `start_at`, `interval_seconds`, `max_runs`, `late_window_seconds`, `end_at` are explicit. Several weekdays become separate plans. Monthly requests require a fixed-interval choice. Money stays in the wallet. |
| `l` — cancel | `autopay_id`, `chain_id`, `plan_id` and `step`. `plan_id` is the 32-byte on-chain ID reported after registration. | Replaces `delegate_address` and `refund_remaining`. The wallet resolves the delegation from its own store/chain state; cancellation does not refund prefunded assets. |

Every amount is `{value, base_units, decimals}`. Validation checks exact equality between decimal and integer units, registered token contracts, recipients, dependencies, timing and caps. Structural JSON validation alone is insufficient. Limits are 16 steps, 3 bridges, 520 slots and 52 weeks; user overrides of agent policy cannot bypass these execution limits.

The agent's `PlanI/J/K/L` types derive from these shared interfaces. Addresses and amounts remain placeholders during interpretation; `display` carries local calendar and policy context. `swapBack` resolves placeholders and removes private metadata before S10/S12 validate the actual envelope. LLM extraction output is not an executable intent.

For an ENS group, the agent asks which members to pay and applies the stated amount to each selected member. One-time groups support up to 100 members; recurring groups support up to 50 (or the smaller configured group limit). Each recurring schedule leg contains the entire selected group, with one operator fee per run. Funding and execution caps include every payee plus the fee; weekly policy counts all payees. Addresses and amounts are fixed at confirmation, and later ENS membership changes do not update them. Finding a saved autopay through any member allows cancellation of the whole matching plan after confirmation. Cancellation by group name and recurring payroll from untrusted content are not supported.

The wallet's execution representation (`IntentSchema`, `BridgeSchema`, `CancelSchema`, `PlanSchema`) also lives here. `toPlan` deterministically derives its UUID from request/step, `from` from the envelope wallet, `asset` from token metadata, `atomic: true`, execution mode and once/recurring schedule. Its internal `version: 1` is a separate representation version, not the wire version. For cancellation, intake validates with a stand-in delegation hash; the wallet resolves the real hash before signing.

`ExecutionReport` covers `intent_result`, `autopay_payment` and `autopay_status`. A successful registration supplies plan/executor identity. Run reports bind the request, autopay, plan, executor, chain, token and slot; payee amount and operator fee are separate. Deduplication uses `(autopay_id, slot, kind)`, so two plans can execute in the same transaction. Bridge reports replace the reserved fee ceiling with the actual ETH fee.

The agent's DB migration preserves historical prefunds, old delegation columns and submitted envelopes. It adds nullable plan identity and schedule metadata, new fee spend kinds and slot deduplication. Old active records without a plan ID require cancellation through their original wallet; they are not reinterpreted as new plans.

Configure `autopay.fee_collector` with the actual operator address, `autopay.fee` in each token and `autopay.late_window_seconds` before enabling new autopays. `bridge.ccip_fee_max_eth` defaults to `0.002` when omitted. Existing running services need a normal rebuild/restart to use source changes.

Build this package first: `npm --prefix packages/protocol run build`. Root and wallet build/typecheck/test scripts run this prerequisite. Offline contract coverage lives in `test/acceptance/shared-intents.test.ts`, `test/unit/D/shared-contract.test.ts`, `test/unit/D/group-autopay.test.ts`, `test/unit/A/shared-intent-migration.test.ts` and `wallet/test/unit/agent-contract.test.ts`; these exercise real validators, HTTP injection, encrypted stores and report transport without a signer or network connection. The updated group pairing prompt has fixture coverage; this does not establish live-model or testnet success.
