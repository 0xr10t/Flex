CONCEPTS

Security

Letting a language model near a wallet is asking for trouble. Models get things wrong, and they can be talked into things. So most of Flexx is plain code built around a few small model calls.

The model doesn't drive

Flexx is a fixed pipeline, not an agent that picks its own tools. Code calls the model at four points (amounts, the kind of request, recipients, and pairing them up), checks every answer, and decides what happens next.

The model never sees real values

Before the model pairs payments with recipients, amounts and addresses are swapped for placeholders. It can only choose between those placeholders, so it can't invent or mistype an amount or an address. Code puts the real values back only after you confirm.

Untrusted text gets its own model

Pasted text, web pages and ENS text records go to a separate, quarantined model call. It has no tools and never sees your request. Anything it pulls out is marked untrusted, needs your explicit confirmation, and can never set up a recurring payment.

The wallet checks again

Before anything reaches MetaMask, the wallet validates the plan on its own, decodes the transaction bytes, and simulates them with eth_simulateV1 across independent providers. If the plan, the decoded calls and the simulation don't all agree, it stops. After sending, it confirms the expected transfers really happened.

Your data stays put

  • Private keys and seed phrases are blocked the moment they're pasted. Flexx only ever needs your public address.
  • The local databases are encrypted with SQLCipher, and the key is kept in your OS keychain.
  • Logs never contain amounts or addresses.
  • Spending limits are set in settings or with /limits, never by the chat.
